How it works

  1. The money sits in a vault nobody can drain

    A factory creates each vault from immutable code, with no full-access key. No person or program holds a key that can sign a transfer out of it.

  2. The agent can only ask

    The agent gets a key that can call one method: request_payment. It can ask to pay. It can't pay.

  3. The contract decides, every time

    Per-payment and daily caps, an allowlist, a hold on repeated payments (the "it failed, please retry" trick), and a lookup in a shared scam registry. If the registry doesn't answer, the payment is blocked.

  4. Lock it for good

    lock_rules() is one-way. After it, nobody, owner included, can loosen the rules or withdraw. Pausing and denying still work.

The platform

Five parts, all live on NEAR testnet, all open source.

  • Vault

    The firewall. Every payment comes out paid, held or blocked, with a reason, recorded on-chain.

    Rules and code

  • Factory

    Creates vaults with no full-access key, on immutable code. If creation fails, you get your money back.

    Code

  • Scam registry

    A shared blocklist. Anyone reports with evidence. Two reporters or a curator flag an account, for every vault at once.

    Code

  • Console

    The owner's web app: create a vault with a NEAR wallet, set limits, approve or deny held payments, lock the rules.

    Open the Console

  • MCP server

    Lets Claude, Codex or any MCP agent pay through a vault, check an address first, and see its own limits.
